01Concepto central15 min

¿Qué es la comunicación entre procesos?

En la clase anterior tratamos cada proceso como si viviera aislado, con su propia memoria y sus propios recursos. En la práctica, muchos procesos necesitan cooperar entre sí: un proceso que descarga un archivo debe avisarle a otro que ya puede empezar a procesarlo; un editor de texto envía datos a la impresora; una aplicación de mensajería recibe datos desde internet y se los entrega a la interfaz que ves en pantalla. A este intercambio de información entre procesos se le llama comunicación entre procesos (en inglés, Inter-Process Communication o IPC).

¿Por qué es necesaria?

Por diseño, cada proceso tiene su propio espacio de memoria, separado del de los demás; el sistema operativo protege esa separación para que un proceso no pueda leer o dañar accidentalmente la memoria de otro. Pero esa misma protección hace que los procesos no puedan compartir datos directamente: necesitan mecanismos específicos, provistos por el sistema operativo, para hacerlo de forma controlada.

La analogía de las oficinas

Cada proceso es como una oficina con la puerta cerrada: nadie puede simplemente entrar y tomar papeles del escritorio ajeno. Si dos oficinas necesitan intercambiar información, deben usar un canal autorizado: un correo, una carpeta compartida, una llamada telefónica. El sistema operativo es quien habilita y vigila esos canales entre procesos.

Sin comunicación entre procesos, un sistema operativo moderno sería inviable: el navegador no podría avisarle al sistema de sonido que reproduzca un video, ni un antivirus podría revisar en segundo plano lo que hacen otros programas, ni podrías copiar un texto de un programa y pegarlo en otro.

02Concepto central20 min

Mecanismos de comunicación entre procesos

El sistema operativo ofrece distintos mecanismos para que los procesos se comuniquen. No todos sirven para lo mismo: unos están pensados para mover grandes volúmenes de datos rápidamente, otros simplemente para avisar que algo ocurrió.

Memoria compartida

El sistema operativo permite que dos o más procesos accedan a una misma zona de memoria RAM. Es el mecanismo más rápido, porque los procesos leen y escriben directamente ahí, sin pasar por el sistema operativo en cada intercambio; a cambio, exige que los procesos se coordinen entre sí para no pisarse los datos.

Paso de mensajes

Los procesos se envían paquetes de información (mensajes) a través del sistema operativo, que actúa de intermediario. Es más lento que la memoria compartida, pero más simple y seguro de coordinar. Dentro de este grupo están las tuberías (pipes, un canal de un proceso a otro) y los sockets (canales que además permiten comunicar procesos que están en computadores distintos, conectados por red).

Archivos compartidos

Un proceso escribe información en un archivo del disco y otro proceso la lee después. Es sencillo de implementar, pero más lento que los mecanismos anteriores porque implica escribir y leer del disco.

Portapapeles (clipboard)

Un caso particular de memoria compartida administrado por el sistema operativo, pensado para que el usuario mueva información entre programas: es lo que usas cada vez que copias y pegas.

03Concepto central15 min

Administración de procesos: la prioridad

Recuerda el estado Listo que vimos la clase pasada: varios procesos pueden estar en ese estado al mismo tiempo, esperando su turno para usar la CPU. La pieza del sistema operativo encargada de decidir a cuál proceso le toca el turno se llama planificador (scheduler), y una de las herramientas que usa para decidir es la prioridad del proceso.

¿Qué es la prioridad?

Es un valor numérico que el sistema operativo asigna a cada proceso y que indica qué tan urgente es atenderlo frente a los demás procesos que también están en estado Listo. A mayor prioridad, más posibilidades tiene el proceso de recibir turno de CPU antes que otros.

¿Quién la asigna?

Por defecto, el sistema operativo asigna una prioridad estándar (normal) a la mayoría de los procesos. Algunos procesos del propio sistema operativo reciben prioridades más altas porque son críticos para que el equipo funcione. El usuario, con permisos administrativos, también puede cambiar manualmente la prioridad de un proceso concreto.

La prioridad no es una promesa absoluta de atención inmediata: es un criterio más que el planificador combina con otros (como cuánto tiempo lleva esperando un proceso, para evitar que uno de baja prioridad nunca llegue a ejecutarse). Este concepto de priorización es el mismo que vas a encontrar más adelante cuando veamos gestión de memoria: allí el sistema también decide, con criterios de prioridad, qué información mantener disponible y cuál puede esperar.

En Windows, el Administrador de Tareas permite ver y cambiar la prioridad de un proceso con seis niveles: Baja, Inferior a la normal, Normal, Superior a la normal, Alta y Tiempo real. Este último nivel es delicado: puede volver inestable el equipo si se asigna a un proceso equivocado.

Actividad · Verdadero o falso

Un proceso con prioridad "Alta" siempre termina antes que uno con prioridad "Normal", sin excepción.

El planificador del sistema operativo decide, entre otras cosas, a qué proceso en estado Listo le da la CPU.

04Práctica guiada10 min

Cambiar la prioridad de un proceso

En Windows, el cambio de prioridad se hace desde el Administrador de Tareas, en la pestaña "Detalles". Sigue estos pasos junto con el docente; los vas a repetir tú mismo en el Taller 2 de hoy.

Pasos

1. Abre el Administrador de Tareas (clic derecho en la barra de tareas, o Ctrl + Shift + Esc).
2. Ve a la pestaña Detalles.
3. Haz clic derecho sobre el proceso que quieras modificar.
4. Selecciona Establecer prioridad y elige el nivel deseado.
5. Confirma el cambio si el sistema lo solicita (algunos cambios requieren permisos de administrador).

Precaución: subir la prioridad de un proceso a "Tiempo real" puede hacer que ese proceso acapare la CPU y que el resto del sistema deje de responder. En el taller de hoy solo se trabajará con niveles Baja, Normal y Alta.
05Investigación10 min

Investiga: algoritmos de planificación

Vimos que el planificador decide, usando la prioridad, a qué proceso le toca la CPU. Pero "decidir con prioridad" se puede hacer de varias maneras distintas: existen procedimientos concretos, llamados algoritmos de planificación, que el sistema operativo puede aplicar. En el video de hoy vas a escuchar los nombres de tres de ellos. Esta es tu consigna de investigación.
